# 天线设计信息理解 MCP 部署指南

## 首版边界

首版不包含 OCR/VLM 模型，也不需要 GPU。服务可以运行并暴露 MCP tools，但 `list_providers` 会明确显示视觉 provider 未配置。开发验收可临时启用 `VerificationEvidenceProvider`，它只读取人工核对的结构化证据，不执行识图。

## Windows 部署

1. 将本目录复制到目标机器的短路径目录。
2. 使用 Python 3.10 或更高版本，并安装项目 `pyproject.toml` 声明的 MCP/Pydantic 依赖；没有联网时，应在联网构建机制作离线 Python 环境包后复制，不在服务运行时安装依赖。
3. 复制配置模板并修改输入/输出路径：

```powershell
Copy-Item .\config.example.ps1 .\config.ps1
. .\config.ps1
$env:PYTHONPATH = "$PWD\src"
```

输入根目录只放待分析文件，输出根目录用于摘要和 JSON 产物，二者不要指向 HFSS 工程目录。

开发/测试证据 provider 通过以下配置开关启用；生产默认保持 `false`：

```powershell
$env:ANTENNA_INTELLIGENCE_ENABLE_VERIFICATION_PROVIDER = "false"
```

## 启动与健康检查

```powershell
python -m antenna_design_intelligence_mcp list-tools
python -m antenna_design_intelligence_mcp run --transport stdio
```

共享 HTTP MCP：

```powershell
$env:ANTENNA_INTELLIGENCE_TRANSPORT = "streamable-http"
$env:ANTENNA_INTELLIGENCE_HOST = "0.0.0.0"
python -m antenna_design_intelligence_mcp run
```

启动后先调用 `list_providers`，确认服务状态和 provider 能力；首版预期 `verification_evidence` 为 `unavailable`。

## 后续嵌入 OCR/VLM 的位置

模型确定后，在联网构建机下载模型并计算 SHA-256，放到离线包单独的 `models/` 目录；新增 provider 只实现 `EvidenceProvider` 合约并在 `ProviderRegistry` 注册。模型文件、GPU runtime 和转换脚本不得提交 Git，也不得让服务运行时联网下载。

后续部署包必须说明：模型名称与版本、许可证、模型目录、摘要、运行时版本、显存要求、provider 配置、离线安装命令、健康检查、禁用方式和回滚方式。替换 provider 不应改动 `AntennaDesignSpec`、MCP tools 或 HFSS MCP。

## 典型交接

```text
inspect_input
→ list_providers
→ extract_document_evidence
→ extract_antenna_design_spec
→ 审核 confirmed/inferred/conflicting/unknown
→ 调用 HFSS MCP 建模
→ validate_design
→ run_simulation
```

规格中未确认的端口、积分线、边界、airbox 或几何尺寸必须先补充，不能静默使用默认值。
