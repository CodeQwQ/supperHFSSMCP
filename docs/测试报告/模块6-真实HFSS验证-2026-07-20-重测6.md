## 根因与影响

本轮失败的直接原因不是 HTTP 或 MCP 协议，也不是本轮已验证的频率扫描参数映射，而是 `connect_hfss(port=53387)` 绑定到了一个空的真实设计：

```text
project: Project14
design: HFSS_8TW
object_count: 0
solution_type: Terminal
```

在没有几何体、材料区域和端口/激励时，HFSS 不具备可求解的 driven design。当前服务允许 Agent 在 `validate_design.valid=false` 的情况下继续调用 `run_simulation`，底层 `analyze_setup` 返回失败，服务层只得到通用的 `Backend reported simulation failure.`，因此不会产生 Solution Data。

影响范围：

- 模块 5：仿真前置校验和求解入口没有阻止空设计进入求解。
- 模块 6：没有真实 SolutionData，无法验证 S 参数读取、阻抗读取、判据分析和报告导出。
- 真实多用户部署：若服务器存在多个 AEDT 会话，必须明确指定工程/设计，避免连接到空项目或错误会话。

## 下一步建议

1. 用 MCP 工作流先在明确的工程/设计中创建贴片天线几何体、材料、边界和端口，再执行 setup、校验和求解。
2. `connect_hfss` 的真实验证必须明确记录 project path、design name 或可识别的 gRPC 会话，不能只依赖当前 active design。
3. 在 `run_simulation` 前增加服务层前置门禁：若最近一次 `validate_design` 为无对象、无激励或无 setup，应返回结构化前置校验错误，不应直接调用求解。
4. 只有在一个完整贴片天线设计真实求解成功并拿到 `dB(S(1,1))` 与 `Z(1,1)` 点后，才能重新判定模块 6 PASS。
