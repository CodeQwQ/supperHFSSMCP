# 模块 9：真实优化返回非有限 S 参数

## 问题现象

专用验收 agent 通过真实 streamable HTTP MCP 连接 Student HFSS 2025.2，连接、创建偶极子、读取 design summary 和设置 design variable 均成功；但调用 `optimize_design_variable` 后，业务结果为 `status: failed`、`best: null`，候选错误为 `value_db must be finite`。

## 复现方式

1. 启动真实 `pyaedt` 后端的 streamable HTTP MCP 服务。
2. 通过 `mcp.ClientSession` 调用 `connect_hfss`，连接 `localhost:53387`。
3. 通过 MCP 创建并读取真实 HFSS design。
4. 切换到 `HFSS_Module9_OptPatch2`，设置 `module9_fresh_var=1mm`。
5. 调用 `optimize_design_variable`，setup 为 `Module9OptPatchSetup2`，候选数为 1。

真实证据见 `docs/测试报告/证据/模块9/mcp-http-results-fresh.json` 和 `server-fresh.stderr.log`。

## 原因分析

AEDT 日志显示该 setup 在本轮求解期间出现 `Error in Solving Setup`，随后 PyAEDT 仍能加载 solution 对象，但返回的表达式数据包含非有限值。当前 `run_simulation` 只依据 `analyze_setup` 的返回值生成 `completed/failed`，没有把求解日志或结果有效性纳入状态判定；结果转换层也允许 `inf/nan` 先进入优化评分，再由分析层抛出异常。

此外，验证脚本复用了历史 design/setup，不能证明优化闭环在一个由当前 MCP 调用完整准备的 design 上成立。

## 影响范围

- 模块 9 的真实优化闭环不能验收通过。
- 模块 9 的偶极子建模和 design variable 设置仍已在真实 HFSS 中成功。
- 可能误报仿真已完成，延迟到结果分析阶段才暴露失败。

## 需要修改的模块

- `src/hfss_agent_mcp/backends/pyaedt.py`：明确识别求解失败和非有限结果。
- `src/hfss_agent_mcp/core/service.py` / `core/optimization.py`：保留候选级失败原因，避免把无效数据当作有效评估。
- 模块 9 真实验收脚本：每次创建独立 design、setup 和 sweep，不复用历史 design。
- `docs/optimization.md` 与模块 9 测试报告：同步新的前置条件和结果状态语义。

## 计划改动

1. 为 PyAEDT 结果点增加有限值校验，并返回可定位的 backend 错误。
2. 为仿真结果补充 solver/solution 有效性检查，禁止“求解失败但 status=completed”。
3. 用全新 HFSS design + setup + sweep 重新执行一次真实 MCP 优化。
4. 由新的专用验收 agent 重新给出 PASS/FAIL；通过后关闭本问题。

## 改动后验证

- 修复前状态：OPEN；修复后真实回归已通过。
- 离线测试：已有 65 项通过，但不足以关闭本问题。
- 真实 MCP/HFSS 修复后回归：新专用验收 agent 使用全新 design、setup、sweep 和 1 个候选完成真实仿真，返回有限 S 参数点、`simulation.status=completed`、`best` 和完整 `evaluations`；结论 PASS。详见 `docs/测试报告/模块9-修复后专用验收-agent-2026-07-20.md`。

问题已关闭。历史失败证据仍保留，用于说明问题曾经真实发生；修复后证据单独保存，避免覆盖测试事实。
